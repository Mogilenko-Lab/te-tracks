# ADR-4 consult — transcript context and species handling

**Ruling: AMEND.** The missing contract is the geometry and provenance of the sequence actually measured. A record can cross several transcript features; a peak or read can touch a different part of that record from the part summarized as “exonic.” Exon subtraction already makes the first release depend on gene annotation. Build normalized transcript geometry before exports and deliver context and subtraction registration together. Keep expression-dependent interpretation in the analysis layer.

This is a source review and proposed contract. Measured facts are accepted from the supplied audit and decision state; no quantifier, build, install, network request, or git command was run. This report is the sole write. File:line citations use workspace-relative paths with these prefixes: **T** = `01_modules/te-tracks`; **I** = `01_modules/.ref/irescue/irescue`; **Q** = `01_modules/.ref/TEsingle`; **S** = `01_modules/.ref/stellarscope/stellarscope`; **M** = `01_modules/.ref/MATES`; **L** = `14761-DM/01_modules/scio/skills`. Biological implications below are interpretation of the proposed geometry and measurement contracts.

## 1. A record × transcript summary needs an exact interval relation beneath it

The unanswered downstream question is: **which bases supporting this observation have which transcript context?** An overlap total answers how much annotated sequence overlaps; it cannot locate that overlap within a peak or read. A nearest-transcript-only table also loses alternative isoforms, overlapping antisense genes, and promoters of transcripts whose bodies never touch the record.

Use the following logical schema. Normalize repeated transcript data into referenced tables; the ledger can expose a joined view. Coordinates with suffix `1` are 1-based inclusive, consistent with the existing catalog (`T/docs/OUTPUTS.md:3`). A suffix `cut0` denotes an interbase coordinate: exon `[a,b]` has boundaries `a-1` and `b`.

| Relation | Required columns and contract |
|---|---|
| Transcript reference | `transcript_key`, exact source `transcript_id`, exact source `gene_id`, nullable `gene_name`, nullable `gene_biotype`, nullable `transcript_biotype`, `chrom`, `tx_start1`, `tx_end1`, `tx_strand`, `tss1`, `tes1`, `structure_status`, and source terminal-completeness flags when supplied. Preserve version suffixes and source disambiguators. Define `transcript_key` by source transcript ID plus genomic locus `(chrom,tx_start1,tx_end1,tx_strand)` and validate its gene association. This handles repeated source identifiers at distinct loci without merging them. |
| Transcript geometry | `transcript_key`, `segment_id`, `segment_kind` (`exon`, `intron`, `promoter`), `ordinal`, `start1`, `end1`; original `exon_id` when available; `promoter_policy_id` for promoter segments. Rank exons/introns in transcript direction. Retain CDS/UTR geometry when present if exposing coding/5′-UTR/3′-UTR labels; absence of those features means unavailable subtype. |
| Record–transcript context | PK `(record_id,transcript_key)` within the selected build/context policy; `relation_flags` (`body_overlap`, `promoter_overlap`, `nearest_tss`, `nearest_tes`, `nearest_exon_boundary`), `relative_strand` (`same`, `opposite`, `unknown`), `body_overlap_bp`, `exon_overlap_bp`, `intron_overlap_bp`, `outside_body_bp`, `promoter_overlap_bp`, `tss_signed_bp`, `tes_signed_bp`, `nearest_exon_boundary_bp`. Keep simultaneous flags; promoter and exon overlap can cover the same bases. |
| Exact context intersections | `record_id`, `transcript_key`, `segment_id`, `overlap_start1`, `overlap_end1`, `overlap_bp`. Segment kind and ordinal come from transcript geometry. Multiple rows preserve exon/intron transitions and all disjoint pieces. |
| Nearest exon-boundary ties | `record_id`, `transcript_key`, `exon_ordinal`, `boundary_cut0`, `boundary_kind` (`donor`, `acceptor`, `transcript_5prime`, `transcript_3prime`), `distance_signed_bp`. Retain every boundary attaining the pair's minimum absolute distance, including coincident boundaries belonging to different transcripts. |
| Record context coverage | One row per record: `record_id`, `context_status`, `has_body_overlap`. Distinguish evaluated records, contigs outside the declared gene-annotation scope, and unsupported structures. An absent context stage is a manifest capability state, `not_computed`; it supplies no biological classification. |

Construct a **sparse** record–transcript relation: include every body overlap, every promoter overlap, and every same-contig transcript tied for the globally nearest TSS, TES, or exon boundary. Retain a pair once with all applicable flags. Thus a nearby transcript has an explicit proximity relation, while a body-overlapping transcript is a candidate host. Preserve all isoforms and ties; a preferred-transcript subset can be a declared downstream selection. “Intergenic relative to this annotation” means no annotated transcript-body overlap on an evaluated contig, independently of promoter proximity.

Introns are gaps between consecutive exon blocks of the same transcript. Validate exon ordering, transcript bounds, and parentage before deriving them. A gene-level union of exons erases the case where one isoform contains an intron and another contains an exon. A single-exon transcript has zero introns. Missing exon structure, multi-contig transcripts, or circular structures require explicit handling or an unsupported status; filling their gaps by assumption would fabricate context.

**Distance definitions must travel with the data.** For record `[a,b]`, transcript strand sign `s` (`+1` or `-1`), and landmark base `p`, choose the closest record base `q=min(max(p,a),b)` and report `s*(q-p)`. This yields zero when the record covers the landmark, negative upstream, positive downstream. Compute TSS and TES distances separately. TSS is `tx_start1` on `+` and `tx_end1` on `-`; TES is the opposite endpoint. For an exon boundary at cut `c`, choose the closest point in the record's interbase extent `[a-1,b]` and apply the same oriented difference. The summary boundary distance is the minimum absolute value; the tie relation preserves signed values and boundary identities. A zero boundary distance includes touching that boundary; base overlap remains separately determined by the interval intersection.

For a promoter policy with upstream extent `U` and downstream extent `D`, include bases satisfying `-U <= s*(x-tss1) <= D`, clipped to contig bounds. Store the resulting coordinates and both parameters. Intersect every transcript's window, regardless of record strand, and report orientation separately. Window extents are policy inputs; a promoter-overlap flag describes that window. Transcript TSSs describe host-gene annotation. A repeat record's oriented endpoint can be a broken internal segment, so a TE-promoter claim needs the later structural evidence.

**The extra landmark ADR-4 misses is TES.** Distance to the annotated 3′ end and terminal-exon geometry are necessary for interpreting a 3′ assay. Genomic distance through an intron and distance along a spliced transcript are different quantities. Label the proposed distances genomic; exon order permits a later spliced-distance calculation for exonic observations.

All of these geometries, orientations, ties, and distances are computable from the pinned annotation and assembly now. Selecting an expressed isoform or an active TSS/TES requires sample-specific evidence. An expression matrix alone can still leave those choices unresolved. Junction-spanning reads, transcript assembly, or suitable initiation/end evidence may be needed. Internal-priming assessment additionally needs the pinned genome sequence and a declared sequence rule. Preserve reference context separately from those analysis findings.

## 2. What each modality can actually conclude

| Modality | Required interpretation and failure prevented |
|---|---|
| 3′ nuclear RNA | Intersect aligned read blocks with the exact transcript segments; use inferred RNA strand, host-relative orientation, TES/terminal-exon position, and junction evidence. A same-direction intronic observation is compatible with host pre-mRNA. The noExon view retains that intron. Distinguishing host transcription, intron retention, internal priming, and autonomous TE transcription needs additional evidence. Removing exon overlap alone leaves those explanations unresolved. |
| 5′ whole-cell RNA, paired-end | Use all alternative TSS/promoter relations, first-exon structure, aligned mate blocks, and the actual cDNA-mate/strand convention. A TE sequence in an expressed host first exon or promoter can support host transcription or a chimeric transcript. A 5′ assay designation supplies neither an exact initiation coordinate for every alignment nor the orientation rule for both mates. |
| Paired-end ATAC | Classify each correctly normalized cut against the exact `peak ∩ record ∩ transcript-feature` geometry. Fragment overlap, peak accessibility, and a cut inside TE sequence are different observations. Both cuts can lie outside a TE traversed by a fragment. Transcript-relative strand is an annotation relation; ATAC supplies no RNA sense/antisense measurement. Preserve the existing cut-shift convention in the run metadata. A nearest TSS supplies proximity; regulatory target assignment requires a separate link. |
| Bulk RNA | Register strandedness, paired/single-end layout, poly(A)/total-RNA preparation when known, multimapper policy, and full-record versus noExon intervals. A subfamily count mixes many genomic contexts. Reference copy fractions cannot partition that count into intronic, exonic, or autonomous expression. Context-specific abundance requires appropriate read-level counting/inference; simple reannotation of an aggregated matrix cannot recover it. |

These requirements are grounded in distinct local consumer behaviors. IRescue intersects split alignment blocks and applies `-s`/`-S` only when requested (`I/map.py:310–327`). TEsingle derives direction from each alignment's reverse flag and converts its aligned blocks to 1-based coordinates (`Q/TEtools/AlignmentIO.py:65–76`); Stellarscope explicitly chooses mate 1 or mate 2 for paired-end strand inference (`S/utils/calignment.pyx:54–68`). Thus the assay's capture end cannot substitute for a tested library-orientation contract. The inspected MATES coverage path uses unstranded overlap calls, then uses TE strand to choose a coverage anchor (`M/MATES/scripts/count_coverage_10X.py:109–133`); its output cannot supply lost RNA direction.

## 3. noExon is complementary, and its registration must preserve pieces

Define the canonical noExon mask as the genomic union of **all exon intervals, including UTR sequence, from all transcripts and biotypes in the pinned gene annotation, across both strands**. Subtract that union independently from each selected canonical record. This is a fixed annotation policy, independent of which genes happen to be expressed. Exons of an alternative or opposite-strand transcript therefore remove sequence even where another transcript calls it intronic. That consequence should be inspectable through the context relation.

Keep every surviving piece registered as:

`(export_path, export_md5, export_row_index, emitted_feature_id, record_id, piece_index, chrom, start1, end1, strand)`.

The build supplies the scope. Assign `piece_index` by ascending genomic coordinates within each record and view. For `subfamily.noExon.saf`, every piece's `emitted_feature_id` is the record's `repName`; repeated GeneIDs are the grouped measurement. Preserve original record coordinates in `rmsk_records`. A piece is a view interval with a parent record, so it receives no new canonical record identity. Keep per-record view status `unchanged`, `trimmed`, `split`, or `fully_subtracted`, together with `retained_bp`, `removed_bp`, and `n_pieces`. Fully subtracted records have zero pieces and an explicit status; their absent output features represent excluded support.

Concrete boundary case: record `101–200`, exon `141–160` produces SAF pieces `101–140` and `161–200`, both registered to the original record. Retained length is 80 bp, removed length 20 bp. A cut at 150 still overlaps the canonical record and its exon context, while it lies outside the noExon counting support. For each record, assert `retained_bp + removed_bp = original_length_bp`, disjoint retained pieces within the parent, and zero residual mask overlap. At grouped-feature level, any sequence-length denominator uses the union of support intervals; overlapping record lengths can overstate covered sequence.

The local recipe performs precisely an unstranded exon subtraction and preserves the grouped GeneID through split pieces (`L/te-reference-saf-build/scripts/build_te_saf.sh:95–124`). It groups by `Subfamily:Family:Class` (`.../build_te_saf.sh:78–86`), whereas current ADR-1/ADR-3 choose bare `repName`. Treat that as an explicit counting-unit migration and register the actual emitted ID; old triple-level runs retain their original resolution.

The two products are **complementary**: context describes all original sequence and candidate transcript relations; noExon defines the sequence available to a particular quantifier. An overlap-bp summary cannot reconstruct the SAF. Exact geometry could regenerate it, but publication provides the tested counting input and its digest. A table joined after counting cannot remove counts from excluded pieces, and changing the eligible intervals can also change multimapper inference.

**Correct the existing “counts each read once” claim.** `T/docs/DECISIONS.md:35–40` and `T/README.md:61` overstate what subtraction guarantees. A paired-end molecule with one aligned block in a gene exon and another in retained TE sequence can enter separate gene and TE runs. The lab driver executes those runs separately and row-binds their matrices (`L/te-gene-featurecounts/scripts/runFeatureCounts_TE_and_genes.sh:122–129,175–194`). More directly relevant to nuclei, TEsingle indexes `transcript` rows (`Q/TEsingle:110–113`) using their complete intervals (`Q/TEtools/GeneIndex.py:166–185,205–218`), so its gene support includes introns. The precise reference guarantee is **exon-disjoint sequence support under the declared mask**. Molecule exclusivity belongs to a joint assignment/counting contract and its tests.

MATES's stock “exclusive” reference has another meaning: it removes whole TE records overlapping the selected gene intervals with `subtract(A=True)` (`M/build_reference.py:127–135`). Register that as a separate interval policy if used; the filename alone cannot establish equivalence to noExon.

## 4. One assembly config is enough, with explicit source capabilities

Keep one `config/<genome>.env`; include organism identity as data in that file and the manifest. A species inheritance layer currently has no separate reader or decision to own. The parser and normalized transcript schema must support the selected source format. Merely substituting a species name into a GENCODE URL would leave that work undone.

Required declarations are organism name/taxon ID; assembly accession/version and contig scope; pinned FASTA, sizes, RepeatMasker `.out`, cross-check table, and alias map; gene provider/release/input format/checksum; annotation contig scope and identifier mapping; context/subtraction policy; and availability/evidence for legacy membership. Assembly patch, primary/alternate-contig scope, and repeat-library provenance belong beside the source pins. Universal logical universe names describe repeat selections within a build; gene-dependent interval views are a separate axis.

| Assembly | Concrete pipeline consequence |
|---|---|
| mm39 / GRCm39 | Keep the audited GENCODE vM37 source as the canonical gene pin (`T/config/mm39.env:5–24`). Normalize its transcript/exon features once and use that result for context and subtraction. Read aliases by named columns: the local map includes scaffold accession changes beyond a `chr` prefix (`_scratch/te-tracks-audit/source/chromAlias.txt:13–18`). The audited packaged legacy source has a recorded digest (`T/docs/PROVENANCE.md:31–33`). |
| hg38 / GRCh38 | Select a pinned human GENCODE release and the matching assembly/contig scope. Primary-assembly and alternate/patch coverage require explicit concordance checks. The local hg38 alias file has empty Ensembl fields for multiple alternate and fix contigs (`M/hg38.chromAlias.txt:4–15`), so a complete Ensembl-named export is conditional on its selected contigs having valid mappings. Preserve exact gene/transcript IDs and disambiguators, including any PAR-associated suffixes. IRescue declares an hg38 `.out` source (`I/_genomes.py:7–8`); this is local evidence of an intended source, with download contents and checksums still to be verified. TEsingle advertises a human curated package (`Q/README.rst:15–19`), whose actual membership must be reconciled before defining `legacy_tetranscripts_hg38`. |
| dm6 / D. melanogaster release 6 | Select a release-6-compatible FlyBase or Ensembl Metazoa gene annotation, preferably a pinned GTF for the first implementation. GENCODE is the human/mouse source in this design. A GFF3 choice requires explicit ID/Parent normalization, including multi-parent exon expansion and feature-type handling. Preserve FBgn/FBtr or other supplied identifiers and accept missing gene symbols/biotype fields. Map chromosome arms such as `chr2L`/`2L`, mitochondrial names, and auxiliary contigs through an assembly-specific map. IRescue declares a dm6 `.out` (`I/_genomes.py:18–19`); MATES documents a custom dm6 GTF path (`M/tutorial/reference_downloading.md:45–49,72–74`). Those references establish possible input routes; they supply no pinned dm6 bytes or verified legacy package here. |

Verify source record concordance, instance-ID scope, taxonomy vocabulary, and export name grammar separately for each assembly. The mm39 measurements establish those properties for that source. If another source reuses instance IDs across contigs or independently processed files, retain that provenance scope in the grouping key. An assembly lacking the required `.out` cannot satisfy the proposed instance contract using the UCSC table's truncated ID. A separately specified records-only capability would be a future extension.

Normalize annotation contigs into the canonical namespace through a validated, unambiguous map. Report all unmatched names, lengths, and scope exclusions. A contig missing from gene annotation retains its repeat records and an explicit context-coverage status. In particular, resist copying the stock MATES normalization: it guesses chromosome prefixes, consults an hg38-specific map, and filters TE contigs to those present in its gene data (`M/build_reference.py:90–120`). Its Mouse/Human paths also select their own assemblies and gene releases (`M/MATES/scripts/Ref2csv.py:7–23`). Custom exports avoid inheriting those source choices. IRescue itself permits partial BAM/BED contig mismatch with a warning (`I/map.py:231–238`), so the reference/analysis preflight must validate concordance independently.

**Legacy availability is conditional.** Publish a legacy universe only after obtaining and pinning the actual packaged file and establishing its record membership. The supplied evidence establishes mm39 compatibility; the local README advertises human support; dm6 package existence remains unverified. An unavailable legacy capability is distinct from an available universe with zero members. Applying the mouse `tRNA`-prefix rule to another assembly would create a new selection with an unsupported legacy label. New repeat classes also require an explicit disposition under the shared universe definitions. Matching universe or repName strings across species establish neither orthology nor comparable autonomous-transcription potential.

No hg38/dm6 source-cache directories were present at the inspected `/data2/users/shared/refcache/{hg38,dm6}` paths. This offline review makes no claim about current remote availability or the existence of files elsewhere.

## 5. Version once; let the ledger retain measurement grain

**Choose the canonical-build model in ADR-7.** Each delivered build has one pinned gene annotation and context policy. A GENCODE revision produces a new BUILD_ID, regenerating context, noExon intervals, registration, and their observed summaries. The RepeatMasker record table can remain byte-identical and retain the same record strings; its digest establishes that reuse. Source checksums and policies must participate in the deterministic fingerprint, so an annotation bump still changes build identity when the resulting intersections happen to be identical. The present fingerprint excludes the manifest (`T/src/release.sh:21–30`); that behavior requires amendment to realize the proposed contract.

Consumers then pin one release and verify that its context and counting support agree. Physically omit BUILD_ID from files contributing to its own hash; attach the enclosing build scope when loading the ledger. Store the gene checksum once in build metadata. Repeating it in every record–transcript key adds no discrimination within that build.

A satellite keyed only by `(rmsk_records_md5,gene_annotation_md5)` is insufficient: promoter widths, transcript selection, alias normalization, and schema/algorithm semantics can change with both inputs held constant. A complete satellite contract would additionally need those policies and an output identity. It is useful later for independently managed comparative annotations, but leaves consumers managing two release scopes and still requires matching the noExon export to the correct context. One canonical build is simpler for the current delivered artifact set. Internal caching by dependency checksums remains compatible with it.

The ledger needs the following connections:

- **`peak_record_overlaps`:** retain `(peak_set_id,peak_id,build_id,record_id)`, intersection coordinates, `overlap_bp`, and fractions with explicit denominators (`peak_length_bp`, full `record_length_bp`). Compute transcript-feature attribution by intersecting this intersection with exact context segments. A record overlapping an exon outside the peak cannot make that peak exonic. Cut counts use the same geometry with the declared cut convention; peak accessibility stays at its original fact key. Promoter proximity also stays distinct from an experimentally supported peak–gene link.
- **`te_feature_registration`:** retain exact exported/output feature identity, resolution, universe, export digest/path, interval policy and record membership; join each membership edge to its retained pieces and view status. Gene-source/context identity resolves through the build. Run metadata additionally records the actual gene-counting annotation/filter, gene feature type (exons versus transcript spans), strand/mate convention, and inference method. These can differ from the canonical annotation used for reference context and require an explicit compatibility check.
- **Quantitative joins:** transcript candidates and membership pieces provide possible support. Use distinct registered feature keys to select facts before aggregating. One subfamily feature with count 7 remains one measurement when it maps to three records, two retained pieces, and five candidate transcripts. Such a selection answers “features whose support includes this context”; estimating abundance originating in that context requires resolved evidence or an explicit allocation model. Preserve direct subfamily inference separately from sums of inferred record measurements.

A reviewer should be able to trace any reported association from the observation to its supported interval, canonical record, transcript-feature geometry, and source release. That trace is the substantive addition ADR-4 needs.

## Final ruling — AMEND

Public DECISIONS.md wording:

> Each build publishes transcript geometry, a record–transcript context relation with exact overlap blocks and transcript-oriented landmarks, and an exon-subtracted view whose retained blocks register to canonical records. These gene-dependent artifacts share the build's pinned gene annotation, context policy, and BUILD_ID, and a gene-annotation or policy revision produces a new build. Each assembly has one configuration declaring species, source providers, contig mappings, and available universes, with legacy membership established against a pinned packaged annotation.
