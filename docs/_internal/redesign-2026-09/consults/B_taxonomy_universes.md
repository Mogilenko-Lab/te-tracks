# Unit B — taxonomy and biological universes

**Ruling:** count consensus names (`repName`) for primary subfamily RNA analyses; preserve each record's original classification and use a separately curated, one-row-per-name hierarchy for rollups. Use `interspersed` for regulatory discovery, report `satellites` separately, and reserve the tRNA-prefix exclusion for historical comparability. Call annotation rows `rmsk_record` and RepeatMasker ID groups `rm_instance`.

Paths below are relative to `/workspaces/Meta-Aging`. Citation abbreviations: **T** = `01_modules/te-tracks`; **R** = `_scratch/te-tracks-audit/report`; **I** = `01_modules/.ref/irescue`; **S** = `01_modules/.ref/stellarscope`. Biological explanations are interpretation, not new experimental findings. No network or new measurements were used.

## 1. Consensus identity and classification answer different questions

`repName` names the reference repeat consensus/model matched by a genomic sequence; it is conventionally called the subfamily here. `repFamily` places that model in a related repeat lineage; `repClass` supplies a broader category such as LINE, SINE or DNA. These fields are copied into `subfamily`, `family`, `class` by the builder (T/src/10_build_master.sh:17–19,31–33,44–49). A consensus represents related copies; it is neither an individual insertion nor evidence that its copies remain mobile. For ERVs, an internal sequence and an LTR can have separate consensus names.

The hierarchy comes from repeat-library curation, historically RepBase and also Dfam, mediated by the library and RepeatMasker release used for the annotation. These ranks are operational library categories, not a uniformly resolved evolutionary tree. A `?` suffix records classification uncertainty, not a new transposition mechanism. Family refinement or reassignment can leave the same consensus name associated with different labels. MER63A–D's hAT-Blackjack/hAT-Tip100 split is consistent with such reassignment; the measured table establishes coexistence, **not the direction, date or correctness of a reclassification** (R/subfamily_multiplicity.tsv:26–33). The source pins identify the UCSC table, but do not establish its underlying library version or accession histories (T/config/mm39.env:14–21).

**Premise → ruling → consequence → caveat:** for subfamily abundance, the operational biological unit is the consensus identity within a pinned annotation. Use `repName`, scoped by reference provenance. The triple is a source-classification assertion about that identity. This prevents taxonomy disagreements from manufacturing separate abundance targets. Caveat: a name collision between genuinely distinct library models would invalidate name-only merging; accession/sequence evidence must resolve that exception, rather than assuming global name uniqueness across releases.

### One canonicalization policy for all 20 names

**Premise:** record frequency is evidence of annotation prevalence, not curatorial authority. **Ruling:** keep exact raw values; curate one canonical row per repName using a pinned library accession/history, retaining the decision's evidence and confidence. **Implication:** abundance remains stable while hierarchy revisions become explicit. **Caveat:** until the evidence exists, publish unresolved fields rather than a majority-vote family.

Apply the following rules to the complete measured list:

| Names | Treatment pending accession-backed curation |
|---|---|
| Eulor8, Eutr15, Eutr16, MER121, MER124, MER131, MER99, UCON2 | Base labels agree after removing terminal `?`. Store that base as a provisional canonical label, with `taxonomy_status=uncertain_source`; preserve which records carried uncertainty. This is normalization, not promotion to a certain assignment. |
| Eulor5B, Eulor6A | `DNA?` is broader than Crypton-A/Crypton. Retain candidate families; family unresolved until evidence supports the specific assignment. |
| Eutr2, Eutr2B, MER136 | Generic DNA versus MULE-MuDR/Merlin: retain candidate families; do not equate a broad label with proof of the specific lineage. |
| MER53, UCON44, X4b_DNA | hAT versus hAT-Blackjack, and TcMar versus TcMar-Tigger: retain the supported broad relationship, leave the precise family unresolved pending curation. |
| MER63A, MER63B, MER63C, MER63D | Competing named families: resolve only from accession-linked library evidence; never choose hAT-Tip100 because it has more records. |

All memberships and label pairs: R/subfamily_multiplicity.tsv:2–41. For these names, normalized class can be DNA with an uncertainty status wherever `DNA?` occurred. Unresolved family is a null canonical field plus explicit status and candidate set; display its counts in a `taxonomy_unresolved` bucket. This bucket must remain distinct from the literal RepeatMasker family/class `Unknown`.

**Evidence standard:** a curated map must identify the exact repName, source/library release, stable accession(s), sequence identity or documented name continuity, authoritative classification entry/change record, canonical family/class and reason. A later library assignment is acceptable as a labelled reinterpretation of the older annotation. Unsupported inference or majority counts cannot silently overwrite it. If library evidence shows distinct models sharing a name, stop canonical merging for that name and register accession-resolved features. Until then, the table above is a conservative proposal, not a completed authoritative map.

## 2. Universes: explicit biological scope

An **interspersed repeat** has copies distributed among other genomic sequence, usually reflecting transposition and subsequent evolution. A **satellite** is a repeat organized primarily in tandem arrays. Centromeric and pericentromeric satellites are therefore a separate organization of repetitive DNA; dispersion of an occasional copy does not convert the whole satellite category into a TE lineage.

The following names are the final recommendation: keep the six requested explicit views, with no extra aliases. Only `all_rmsk` is the unrestricted catalog. No family-prefix filter applies except in the named legacy view. Counts are annotation records, not intact elements or measured molecules (R/policy_universes.tsv:2–8; full source R/AUDIT.md:39–40).

| Final name; records | In / out in RepeatMasker vocabulary | Premise and downstream use | Caveat / must never be called |
|---|---|---|---|
| `all_rmsk`; 5,320,771 | Every row, every repClass and repFamily; no exclusions. | A complete source catalog supports reproducible selections, masking and later reclassification. | Limited to this assembly/run's annotations. Never “all TEs” or “all genomic repeats.” |
| **`interspersed`; 3,764,949 — regulatory default** | repClass in SINE, LTR, LINE, DNA, RC, Retroposon, Unknown, Unspecified, DNA?; everything else excluded. Includes all three tRNA-prefix SINE families. | Regulatory sequence can derive from ancient DNA elements as well as retrotransposons. RC denotes rolling-circle elements; Retroposon is the library's named category, included alongside LINE/SINE/LTR. | Unknown/Unspecified are provisional candidates, DNA? is tentative DNA-element classification. Never “confirmed TEs,” “active TEs,” or “retrotransposons.” |
| `interspersed_plus_satellite`; 3,802,177 | Previous set plus repClass Satellite; structural-RNA and simple/low-complexity classes excluded. | A combined repeat-associated analysis or comparison can use one interval selection while retaining a satellite/interspersed axis. | Always stratify interpretations. | `satellites`; 37,228 | repClass Satellite only; all other classes excluded. | A separate aging axis for tandem-repeat chromatin and repeat-associated RNA. | Reference representation and multi-mapping limit coverage of arrays. Never “all centromeres,” “all tandem repeats” or “TE expression.” |
| `legacy_tetranscripts_mm39`; 3,799,629 — comparability only | `interspersed_plus_satellite` with repFamily beginning `tRNA` excluded. | Reproduces the packaged TEtranscripts mm39 GTF interval selection 1:1, enabling controlled historical comparison (T/docs/PROVENANCE.md:31–37). | Interval equivalence does not imply label or quantification equivalence; labels differ (T/docs/PROVENANCE.md:54–82). Never “TEtranscripts default biology,” “complete SINEs” or the generic default TE universe. |

**Unclassified records — premise:** uncertain origin does not make sequence uninteresting for regulation. **Ruling:** retain Unknown/Unspecified/DNA? in the inclusive `interspersed` selection, explicitly labelled as provisional. **Implication:** candidate regulatory intervals survive; repeat conclusions can be checked after removing these classes. **Caveat:** their inclusion is a policy, not proof of interspersed origin; a TE-specific mechanistic claim needs stronger annotation evidence.

**Satellites — premise:** loss or redistribution of heterochromatin and altered satellite-associated transcription are plausible aging questions distinct from mobilization. **Ruling:** give satellites their own analysis axis, including centromeric/pericentromeric context where independently supported. **Implication:** changes in array accessibility/RNA remain visible instead of disappearing into a large TE total. **Caveat:** an aging association alone establishes neither chromosome instability nor causality; short reads and incomplete array representation constrain locus claims.

**Structural RNA — premise:** repClass snRNA/scRNA/srpRNA/tRNA/rRNA marks structural-RNA-related annotations, potentially including pseudogenes; the class name does not certify a functional RNA gene. **Ruling:** exclude them from biological TE universes, retain them in `all_rmsk` or an explicit RNA/QC selection. **Implication:** RNA-gene signal is not relabelled TE activity. **Caveat:** a TE derived from such an RNA belongs by its TE classification—SINE/tRNA is the essential example. Nor are all these RNA classes uniformly Pol III products; avoid that collective rationale in T/docs/DECISIONS.md:55–57. A tool-specific comparability set may include them: IRescue's automatic filter retains snRNA (I/irescue/map.py:115–132), which is a software policy, not a biological endorsement.

**Simple_repeat/Low_complexity — premise:** these describe sequence organization/composition, not transposition ancestry. **Ruling:** exclude them from TE selections, retain them in `all_rmsk`; use explicit QC/masking or tandem-repeat questions when warranted. **Implication:** they can explain mapping and accessibility biases without dominating TE summaries. **Caveat:** “only ATAC QC” is too restrictive: RNA mapping QC and genuine tandem-repeat biology can also require them. They should never silently become TE features. Their distinct scale is measured in R/class_census.tsv:3,7.

## 3. The tRNA-prefix legacy

LFSINE_Vert, MamSINE1 and AmnSINE2 are ancient SINE lineages: nonautonomous retrotransposon-derived sequences with tRNA ancestry, propagated historically using machinery supplied in trans. Conserved copies can acquire regulatory functions long after mobility is lost. The three family labels describe ancestry, not three collections of ordinary tRNA genes. Their exact family/name pairs and losses are R/trna_prefix_dropped.tsv:2–4; the local interpretation as ancient conserved vertebrate/amniote SINEs is T/docs/DECISIONS.md:60–66.

**What the packaging evidence supports:** a prefix exclusion reproduces the packaged interval set; the current builder implements the exclusion directly on repFamily (T/src/10_build_master.sh:28–33; T/docs/PROVENANCE.md:21–37). A likely explanation is an overbroad attempt to remove structural-RNA annotations that also caught tRNA-derived SINE family names. **The original packaging script and rationale were not available in the inspected material, so that motivation remains an inference.** Do not turn it into a documented TEtranscripts algorithmic requirement.

**Premise → ruling:** 2,548 records are few in the total but could contain a decisive enhancer. Restore all three families in biological views; retain their removal only in `legacy_tetranscripts_mm39`. **Implication:** mouse immune-aging analyses can detect accessibility, motifs, peak–gene links or TE-associated host RNA at these ancient sequences. **Caveat:** local evidence does not establish an immune-aging role for any particular copy; conservation supports prioritization, not a mechanism. RNA from a host transcript containing an old SINE is not evidence of renewed retrotransposition. A null global count effect would not justify deleting the relevant local regulatory annotation.

## 4. Name the record and the grouping separately

**Row: `rmsk_record`, key `rmsk_record_id`.** Premise: this is one source annotation row with an interval. Implication: ledger tables `rmsk_records` and `peak_repeat_overlaps` can distinguish annotation overlap from an experimental `atac_fragment`; feature registration declares its resolution explicitly. Caveat: a record can represent only part of a biological element. `repeat_record` is less source-specific; `repeat_hit` emphasizes alignment; `repeat_segment` could also mean a subsequently clipped interval; `annotation_fragment` retains the fragment collision. `rmsk_record` is the clearest namespace.

**ID-linked group: `rm_instance`, key `rm_instance_id`.** Premise: the `.out` ID records RepeatMasker's grouping; it can unite separated records and different consensus names. Implication: represent a group-to-record membership relation, preserving disjoint intervals and each record's raw taxonomy. Scope IDs by assembly and pinned source/run; a bare integer is insufficient. Caveat: neither grouping nor naming proves an intact insertion, promoter or provirus. Reserve `insertion_candidate` for a downstream structural hypothesis with supporting validation; `repeat_instance` hides who assigned it. Measured multi-record groups reach 22 records (R/out_fragments_per_insertion.tsv:2–19); mixed-name membership and the structural-interpretation limit are documented in R/AUDIT.md:41–45,126–127.

Use the `.out` ID for this relation, not UCSC's `rmsk.id`: the latter has only nine observed values and cannot link instances (R/AUDIT.md:36–40). The current builder copies that UCSC field into `rmsk_id` (T/src/10_build_master.sh:33,41–49), despite the linkage description in T/docs/OUTPUTS.md:26. Preserve it under an explicitly source-qualified field if retained. Keep record identity independent of taxonomy canonicalization, and never copy an instance-level RNA count onto all member records. The observed coordinate-only collisions also require the name-bearing record key, scoped by reference, rather than coordinates alone (R/AUDIT.md:56–60,122–123).
