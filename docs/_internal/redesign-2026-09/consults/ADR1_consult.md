# ADR-1 consult — counting unit and taxonomy

**Ruling: AMEND.** Retain repName as the default aggregate feature within a pinned annotation. The missing contract is the distinction between an annotation identity, the features competing during assignment, and the level subsequently reported. Choosing a level can change which molecules survive, how UMIs collapse, and how ambiguous evidence is allocated; a taxonomy join cannot reproduce those changes.

This is a read-only review of the supplied decision state, audit, consultations and local implementations. Measured facts are accepted. Numerical examples below are deductions from code, with their assumptions stated; no quantifier, build, installation or network operation was run. This document is the sole write.

Citation paths are relative to `/workspaces/Meta-Aging`: **T** = `01_modules/te-tracks`; **I** = `01_modules/.ref/irescue/irescue`; **S** = `01_modules/.ref/stellarscope/stellarscope`; **E** = `01_modules/.ref/TEsingle`; **M** = `01_modules/.ref/MATES`; **R** = `_scratch/te-tracks-audit/report`; **K** = `.agents/skills`. Each abbreviated reference identifies a local file and line range.

**1. Keep the operational name; qualify what it identifies.**

“repName = the consensus” promises more than the inputs establish. The retained source schema supplies a name, classification and consensus coordinates, while its model accession, model version and consensus sequence are absent (`_scratch/te-tracks-audit/source/rmsk.sql:23–40`). The configured source pins likewise identify annotation files, rather than the underlying repeat-library release (`T/config/mm39.env:13–21`). Treat a repName feature as **all selected records bearing that source name**. Its equivalence to one library model remains an evidence claim. In `all_rmsk`, the same operational name field also covers repeat categories whose labels have different biological meanings.

| Candidate default | Decision and consequential limitation |
|---|---|
| repName within the pinned annotation | **Keep.** It preserves the resolution already available and avoids manufacturing competitors from conflicting taxonomy labels. A source-name feature may still contain unresolved model identity. Scope counts by BUILD_ID, feature level and feature ID; export display names can remain short. |
| Family, with subfamily as drill-down | **Offer as a separate assignment view.** A family count cannot yield a subfamily drill-down without the original assignment evidence or another quantification. Coarsening can hide opposite responses among member names, and library families have uneven biological breadth. A family default also makes unresolved curation an immediate assignment decision. |
| Dfam accession | **Use as an evidence-backed cross-reference when available.** Require the library release and accession/model version or equivalent provenance. Adoption as the universal key would first require a complete, verified mapping of this annotation, including historical or unmapped names. No such mapping is supplied locally. A modern accession lookup alone cannot establish which model produced an older annotation. |
| Consensus-sequence checksum | **Use as a sequence-version fingerprint when the actual sequence is available.** A revised consensus changes the digest while biological continuity may persist; identical sequence bytes do not establish identical classification or locus orthology. Define sequence normalization and orientation before comparing hashes, and identify whether the fingerprint covers a consensus sequence or a model. Genome-copy sequence is a different object. |

Retain accession and sequence evidence as a relation that can express aliases, splits, merges and unresolved links. If evidence establishes two different models behind one source name, distinguish their records only where provenance allows that assignment. A count already collapsed across those models remains an aggregate with unresolved composition.

For hg38, a shared table keyed solely by repName would silently assert that every reused string denotes the same model and taxonomy as mm39. Within each snapshot, one canonical row per name is appropriate; across snapshots, key the mapping by assembly, pinned annotation-source digest, repName and taxonomy revision. Count tables already carry BUILD_ID, so this requires namespace columns and mapping provenance, rather than another global annotation-ID service. Cross-species equivalence must be a separately evidenced relation: equal names can be tested as candidate aliases, while equal family labels express a selected comparison rank. Even a verified shared model leaves mouse and human genomic copies and assay opportunity distinct. No hg38 collision census or accession history was available in this review, so these are schema requirements, rather than claims of measured human conflicts.

**2. Publish family assignment explicitly; preserve the estimator behind every total.**

The current “three levels” also implies a hierarchy that the data do not possess. Records partition into RepeatMasker instances and into source names along different axes: a mixed-name instance crosses subfamilies. A single count on that instance has no uniquely determined allocation to its constituent names. Family/class summaries are valid only where each quantified feature has one supported parent or an explicit residual destination (`R/AUDIT.md:41–45,126–127`).

The four requested estimators make the consequences concrete:

| Estimator | Verified behavior and implication for ADR-1 |
|---|---|
| **Bulk featureCounts with Random-One input** | The lab driver uses `-M -F SAF -s 0 -p --countReadPairs -B -C`, with neither `-O` nor `--fraction` (`K/te-gene-featurecounts/scripts/runFeatureCounts_TE_and_genes.sh:122–129`). Random selection is upstream: the local STAR recipe requests random order, one emitted alignment and seed 777 (`K/star-te-preprocessing/SKILL.md:98–115`). A fixed, accepted fragment assigned to one subfamily can be summed into its family. Regrouping the SAF can nevertheless change multi-feature overlap eligibility: a fragment hitting two subfamilies in one family can become unambiguous at family resolution. Treat that as a required featureCounts fixture; its C implementation was unavailable in the inspected checkouts. Pin the BAM and alignment contract as well as the SAF. A BAM retaining one selected alignment has already discarded the alternatives required by a later EM analysis. |
| **IRescue** | BED field 4 supplies the candidate identity; custom BED returns directly (`I/map.py:61–84`). Candidate sets feed feature-dependent UMI deduplication, then binary compatibility EM with uniform initialization. Unique-feature counts are accumulated separately and added after EM; they enter its optional support filter, rather than its abundance initialization (`I/count.py:32–36,119–208,249–297`; `I/em.py:4–20,60–79`). Direct family inference can therefore differ from summed subfamily inference through deduplication, support filtering and allocation. |
| **Stellarscope** | The selected GTF attribute groups records before assignment (`S/annotation/_intervaltree.py:41–60`). Each alignment receives its highest-overlap feature, and candidate alignments to one feature are reduced to the best score-plus-length representative (`S/utils/model.py:51–67,519–535`). Grouping changes candidate scores and ambiguity; the EM priors also depend on the number of features (`S/utils/model.py:140–194,229–244`). Moreover, default `best_exclude` discards tied best posterior assignments (`S/cmdopts/stellarscope_assign.yaml:126–147`; `S/utils/model.py:431–448`). Summing the emitted locus matrix can lose evidence that was perfectly identifiable at subfamily level. Record pooling mode, priors and final reassignment mode alongside inference level. |
| **TEsingle** | Its feature key is the four-part `transcript_id:gene_id:family_id:class_id`, with rows mapped onto that composite (`E/TEtools/TEindex.py:315–364`). The proposed record IDs therefore produce record-level TE features. Gene-only counts, ambiguous TE/gene candidates and anchored gene-plus-TE candidates take different paths; the latter use a cell-level category-derived allocation before EM (`E/TEtools/Counters.py:19–48,89–125,184–201`). The gene index uses transcript rows, making gene annotation and intronic overlap part of this estimator (`E/TEsingle:106–112`). Finally the output rounds each feature to integers (`E/TEsingle:156–169`). A summed record matrix is a particular derived subfamily result, with losses from rounding; it cannot stand for direct subfamily fitting. Changing only `gene_id` leaves record-specific `transcript_id` values in the assignment key. |

Two small counterexamples make the distinction testable:

- **Different EM allocation:** six independent molecules have identical candidate sets `{A1, A2, B}`, with A1/A2 assigned to family F and B to G. Assume distinct, nonconnecting UMIs and adequate support. IRescue's binary matrix and uniform initialization give two counts per subfamily, hence family totals **F=4, G=2**. Replacing candidates with the family set `{F,G}` gives **F=3, G=3**. Both are fixed points of the cited update. The difference exposes an unidentifiable allocation selected by feature parameterization; it establishes neither estimate as biological truth.
- **Lost identifiable evidence:** one molecule ties between two loci belonging to one subfamily. Stellarscope's `best_exclude` can emit zero for both loci, so their sum is zero. A feature containing both loci has one candidate and can retain the molecule, provided the overlap passes. Family sums cannot recover evidence discarded at a finer level.

There is a further IRescue trap: two distinct molecules with the same UMI and disjoint subfamily candidate sets can remain separate; merging their subfamilies makes those sets intersect and can connect their deduplication graph (`I/count.py:32–36,137–150`). Thus even the total assigned molecule count can change with resolution.

**Concrete export amendment:** add `interspersed/family.bed` to the initial deliverable, plus its registered record membership and taxonomy revision. Repeat the canonical family feature ID across the original blocks, preserving strand and gaps. Use the pair `(canonical_class, canonical_family)` as the readable family identity within that taxonomy revision. For unclassified or unresolved names, retain separate residual features keyed by source name and reason; these are declared fallback groups in this view. This preserves their support without treating all unrelated unknown sequences as one biological family. An optional reporting total may aggregate residuals under an explicitly labelled category.

This makes family the fourth supported assignment grouping. A family SAF is warranted when direct bulk family counting is requested; a complete format-by-level grid adds little. A family GTF for TEsingle needs its own composite-key convention and parser fixture. The initial family BED supports the concrete IRescue comparison; other adapters remain explicitly scoped to their tested contracts.

Run registration must separate **assignment level**, **reported level**, **measurement unit** (UMI, read pair, cut, interval overlap), **estimator/output mode**, exact export/universe/interval mask, taxonomy revision and any aggregation parent. For a reported family total, `assignment=subfamily, report=family` and `assignment=family, report=family` identify different analyses. Feature membership alone cannot recover estimator settings, censored alignments or UMI evidence. Retaining original alignments or suitable assignment intermediates belongs to the analysis pipeline.

**3. IAPEz-int measures an internal-component annotation.**

An IAPEz-int RNA count supports RNA associated with intervals carrying that internal-model name. It can combine defective copies, portions of reconstructed elements and TE-containing host transcripts. A rise alone leaves promoter origin, intact provirus abundance and mobilization unresolved. An LTR-model total can additionally mix solo LTRs with LTRs associated with internal sequence. Globally joining a presumed LTR partner to IAPEz-int conflates lineage membership with genomic structure; removing `-int` from names cannot supply that structure.

Publish the source RepeatMasker-instance relation now and retain per-record consensus coordinates. **Defer a named `erv_unit` counting export until a structural stage supplies validated membership.** The audit expressly corrected its earlier claim that the `.out` grouping delivered provirus structure (`R/AUDIT.md:126–127`). This also keeps the annotation projection within the owner's stated scope.

That structural stage should distinguish two relations: a versioned, evidence-backed map of compatible LTR/internal models, allowing multiple partners; and assembly-specific candidate units linking actual records. Candidate validation needs compatible strand/order, consensus coverage, genomic separation, nesting and ambiguous-partner checks. Record component roles such as internal, 5′ LTR, 3′ LTR, LTR of unresolved role, solo candidate and partial unit. Preserve incomplete and ambiguous cases explicitly. A biologically justified unit may span multiple source instance IDs; one source ID may also require rejection as a proposed unit.

For an accepted unit, a counting export uses the union of its accepted annotation blocks and names that support precisely. A genomic bounding span or reconstructed full-element sequence is a separate definition. Joint assignment/deduplication must occur over the unit's blocks: adding already inferred LTR and internal counts can count one molecule twice, and assigning a unit count to each component duplicates it again. A mixed-name unit receives its own structural/lineage annotation; forcing one constituent repName onto it conceals the measurement. In Stellarscope, block-gap correctness still requires the existing endpoint/gap fixture: its merger explicitly joins intervals separated by distance 1 (`S/annotation/utils.py:17–45`).

**4. The modalities expose different unanswered questions.**

These are biological interpretation limits and proposed analysis contracts, rather than new measurements or claims that one platform resolves transcript origin automatically.

| Modality | What repName alone leaves unanswered; required distinction |
|---|---|
| **3′ nuclear RNA** | Intronic host pre-mRNA and captured TE-derived transcripts can support the same internal-repeat feature. Exon subtraction leaves intronic sources available. Report TE-associated RNA, preserve orientation and later transcript-context links, and state the molecule-level policy for reads compatible with both gene and TE. A transcript-context table enables investigation but does not retrospectively resolve a collapsed UMI. TEsingle's full-transcript gene index changes the competition here; its raw-UMI cell cutoff also changes the population compared (`E/TEsingle:92–93,106–112,138–144`; `E/TEtools/Counters.py:244–250`). |
| **5′ whole-cell RNA** | LTR-promoter-associated signal, internal sequence and host read-through require separate support. Verify which sequenced mates contain cDNA and how their orientation is interpreted. TEsingle appends each alignment under its query name and derives strand from each read's reverse flag; this path has no mate-aware orientation branch (`E/TEtools/AlignmentIO.py:60–76`). IRescue also intersects individual alignment blocks (`I/map.py:289–332`). Stellarscope explicitly distinguishes paired FR/RF from single-end F/R (`S/utils/calignment.pyx:54–68`). A 3′ layout fixture cannot certify the 5′ paired layout. |
| **Paired-end ATAC** | A fragment overlapping a TE with both cuts outside answers a different question from cuts within TE sequence. One fragment can overlap an LTR, an internal component and a host interval. Direct family coverage can be recomputed from deduplicated fragments/cuts over the specified interval unions; adding record or peak-overlap counts can inflate it. RNA subfamily support gives no allocation among these accessible copies. Retain the owner’s cut-versus-overlap distinction and treat an ERV promoter as a structurally located component. |
| **Bulk RNA** | Read-pair counts and exon-masked support have different meanings from captured UMIs over full repeat intervals. A pair can touch gene and TE sequence in separate blocks, so exon subtraction by itself cannot guarantee exclusivity between separately counted gene and TE matrices. Declare the pair-level assignment policy and verify it. Cross-species family totals additionally depend on annotated copy number, retained sequence, mapping opportunity and library preparation; equal taxonomy labels supply a grouping, rather than a normalization denominator. |

The annotation repository supplies identities, support intervals and provenance. The analysis run owns these measurement choices. This preserves a modality-independent catalog while making its outputs interpretable.

**5. “Canonical” needs an accountable, independently versioned policy.**

Assign accountability to the project maintainer (Anton, or a named delegate); record an identified reviewer for classification overrides. A first release can conservatively retain conflicts as unresolved. Authoritative resolution requires a source-library record or documented revision history linked to the actual annotation name/model. A modern classification is acceptable as an explicitly dated reinterpretation supported by accession continuity or sequence/model evidence. Record abundance and the fact that one label looks more specific establish neither authority nor revision direction.

Use one small, tracked curation input with an independent taxonomy revision and digest. Each decision records the source namespace/name, rank affected, proposed label, evidence locator and pinned evidence version/digest, rationale and reviewer. Deterministic normalization rules receive a policy version. The generated canonical table has exactly one row per source-name key and **rank-specific statuses**: class may resolve while family remains uncertain. Distinguish source-concordant labels, source uncertainty, curated resolution, unresolved conflict and source-unclassified values. Calling every unchallenged source label “curated resolved” would overstate the evidence.

The build manifest pins the curation digest/revision; revised delivered taxonomy produces a new BUILD_ID while the previous build remains immutable. Independent taxonomy versioning means the same curation revision can be reused across builds, and a curation change can be identified separately from coordinate or export changes. It needs no taxonomy service.

Suppose `MER63A` has 100 counts under one fixed subfamily assignment run. A later family reassignment leaves those 100 counts and their original BUILD_ID intact. A newly derived family summary records the old count run and the new taxonomy revision, and moves that one contribution once. If the original run fitted families directly, its family total generally contains contributions from several source names; extracting MER63A's contribution requires preserved assignment evidence or requantification. The same applies to splitting a previously merged source-name feature. Pinning a new taxonomy cannot recover discarded resolution.

TEsingle makes this boundary especially important: taxonomy occurs inside its assignment key. With a fixed unique record ID, changing its parent label can be merely a row rename; with shared grouping IDs, inconsistent or changed family/class labels can split or merge actual candidates (`E/TEtools/TEindex.py:329–364`). Keep raw source taxonomy in the initial record GTF and apply canonical reporting through registration. An adapter intentionally using canonical taxonomy must pin it as an assignment input.

**6. Preserve `?` and `Unknown` in raw fields; make canonical handling explicit.**

Keep exact repName, repFamily and repClass in `rmsk_records` and `taxonomy_rmsk`. Apply terminal-`?` normalization only to the relevant classification field in the canonical map, preserving a per-rank uncertainty flag and original candidate labels. Do not apply a blanket character replacement to repName. Suffix normalization can establish agreement between labels while their source uncertainty remains. A competing specific family requires separate evidence; the measured multiplicities include both situations (`R/subfamily_multiplicity.tsv:6–15,26–37`).

Keep literal source `Unknown` and `Unspecified` distinguishable. In the canonical layer, represent an unclassified parent with a null classification and `source_unclassified` status; represent conflicting classifications with `unresolved_conflict` and their candidate set. For exports requiring strings, generate registered residual IDs carrying the reason and source name. Replacing `Unknown` with repName would invent a family assignment, although a per-name residual counting group is useful. Preserve any legacy relabelling only in its named compatibility view (`R/alias_family.tsv:3–16`).

This affects software behavior as well as wording. MATES groups model support by its `TE_fam` field and explicitly drops keys ending in `?` or exactly equal to `Unknown` (`M/MATES/scripts/calculate_MU.py:191–194,278–294`). Removing suffixes or rewriting that value can admit features previously excluded by the model preparation. The comparison is to the actual exported string: `class/Unknown` differs from exact `Unknown`. An adapter must report its emitted group IDs and eligibility; raw-table cleaning is an unsafe place to change that policy.

**Final ruling — AMEND. Proposed public DECISIONS.md text:**

> te-tracks publishes record, RepeatMasker-instance, repName subfamily and canonical-family feature views with explicit record membership, with identities scoped to the pinned annotation and subfamily as the default aggregate view. Raw labels remain exact, and an independently versioned, evidence-backed taxonomy map defines family views and rollups with explicit uncertainty, unclassified and conflict statuses. Each analysis records its assignment level, reporting level, measurement unit, estimator and taxonomy revision; ERV-unit views use separately validated structural memberships.

Execute these when the relevant adapters are implemented.
