# Unit A — consumer annotation contracts

## Ruling proposed

Publish one agreed annotation universe through **six required files**, plus an instance BED when instance-level IRescue is requested. Keep record identity, RepeatMasker instance membership, and taxonomy as separate fields. One GTF can serve TEsingle and Stellarscope by carrying both record and instance attributes. MATES needs a dedicated CSV/BED pair. These recommendations are conditional on the parser fixtures below; this review did not execute quantifiers.

## 1. Exact consumer contracts

### IRescue

- **Input and identity:** `-r/--regions` accepts plain or gzipped tab-separated BED with at least four fields; field 4 is the quantification feature. Custom input returns unchanged before auto-annotation or instance reconstruction. BED6 supplies strand. Repeated field-4 values therefore supply the grouping, whether records, subfamilies, or instances (`I/map.py:61–84,326–332,369–387`). `--locus-level` requires `disabled`, `fragment`, or `instance`; it is not a bare switch (`I/main.py:103–113`).
- **Names:** feature sets are comma-separated internally; commas split one name into multiple features. `gawk` reads `$1`, so whitespace truncates names. `#...` is removed from the **second, display-name column** of `features.tsv.gz`; the first ID column remains intact, and counting indexes that first column. Under locus mode the display regex stops before `~`. Therefore `#` is unsafe for identical ID/display-name round-trips, although it does not itself destroy the primary ID. `|`, `:`, and `~` without `#` are not split here (`I/map.py:372–387`; `I/count.py:57–62,75–84`).
- **Coordinates, strand, contigs:** custom BED is passed directly to bedtools, hence 0-based half-open. Auto `.out` start is decremented; any non-`+` RepeatMasker strand becomes `-`. `--strandedness forward` uses `-s`, `reverse` uses `-S`, default unstranded uses neither (`I/map.py:154–159,310–327`; `I/main.py:156–164`). Contigs match literally; BAM contigs with mapped reads absent from BED are warned about and skipped, with failure only if none remain (`I/map.py:217–246`).
- **Auto annotation:** skips classes `Low_complexity, Simple_repeat, rRNA, scRNA, srpRNA, tRNA`; no family filter. Default label is `subfamily#class/family`; fragment mode appends a per-label ordinal. Instance mode reads `.out` field 15, shares a label across the original blocks, and joins each taxonomy set with `|`; it does not fill intervening gaps (`I/map.py:115–189`).
- **Output/cells:** `features.tsv.gz` contains observed feature IDs; barcodes come from mapped, filtered overlaps, not a complete input whitelist. Missing/invalid CBs and missing, N-containing or homopolymer UMIs are dropped; there is no minimum-cell-UMI cutoff in this path. A whitelist filters alignments before overlap (`I/map.py:289–306,379–388`; `I/count.py:301–316,424–432`).
- **Recommendation — premise:** custom BED determines the feature grouping. **Implication:** pin BED4 names and use explicit locus flags for provenance; repeated instance names across separate BED6 rows give instance counts without counting gaps. **Caveat:** a locus flag cannot reconstruct instances from a custom per-record BED; annotation choice, rather than the flag alone, defines resolution (`I/map.py:61–84`).

### Stellarscope

- **Input and identity:** plain GTF via ordinary `open`; default column-3 feature type `exon`, default feature attribute `locus`, configurable through `--feature_type` and `--attribute`. Rows lacking the chosen attribute are skipped with a warning. All rows sharing that attribute become one feature; overlapping/nearby blocks are merged. There is no inference of RepeatMasker instances or subfamilies (`S/annotation/utils.py:103–115`; `S/annotation/_intervaltree.py:34–60`; `S/cmdopts/stellarscope_assign.yaml:40–56`). No annotation downloader/class-family filter occurs in this input path.
- **Names:** attributes must match `(\w+)\s+"(.+?)";`: use word-character keys, nonempty double-quoted values and terminating semicolons. Values have no colon/pipe/comma split in this parser; exclude quotes, semicolons and line/tab delimiters for a portable writer. Reserve `__no_feature`, the default internal sentinel (`S/annotation/utils.py:60–61,94–96`; `S/cmdopts/stellarscope_assign.yaml:52–56`).
- **Coordinates — release gate:** nominal input is 1-based inclusive GTF. The default intervaltree stores `[start,end+1)`, but queries use pysam `get_blocks()` unchanged and then also add 1 to block end. There is **no start conversion between those paths**. For GTF `101..110`, a right-adjacent BAM block `[110,111)` can receive a one-base overlap. Additionally, `merge_neighbors(distance=1)` fills a one-base genomic gap between same-feature GTF blocks. These are source-level boundary defects to reproduce, not grounds to invent a shifted GTF (`S/annotation/_intervaltree.py:55–60,78–84`; `S/annotation/utils.py:17–45`; `S/utils/calignment.pyx:95–104`; `S/utils/helpers.py:114–122`).
- **Strand/contigs:** default `None` uses an unstranded chromosome tree; contrary to option-help wording, that path does not create separate sense/antisense feature names. `--stranded_mode F/R` applies to single-end, `FR/RF` to paired-end. F follows read strand, R reverses it; FR follows mate 1, RF mate 2. Contigs are literal BAM reference names used as tree keys; absent references yield no hits (`S/annotation/__init__.py:28–36`; `S/annotation/_intervaltree.py:29–32,78–84,156–166`; `S/utils/calignment.pyx:54–68,87–89`; `S/utils/model.py:520–535`). The advertised alternative `htseq` backend is rejected by the current factory (`S/annotation/__init__.py:28–36`).
- **Output/cells:** `features.tsv` writes the feature index strings directly; the matrix uses that order. Whitelisted cells are retained in the final barcode order, including empty cells; otherwise only tracked overlapping cells appear. Missing CB, non-whitelisted CB, and missing UB unless `--ignore_umi` cause read skips. No numeric cell-depth threshold is applied in these paths (`S/utils/model.py:1090–1126,1307–1311,1367–1387`).
- **Recommendation — premise:** the selected GTF attribute defines resolution, while current boundary arithmetic is suspect. **Implication:** one multi-attribute GTF supports record and instance runs; gate biological use on endpoint/gap tests. **Caveat:** switching attributes to group instances is a new statistical feature definition, and the default merger can include one-base gaps. The current threshold assignment selects one maximum-overlap feature per alignment, with strict `overlap > length × threshold`, so equal-coordinate competing annotations also need a tie fixture (`S/utils/model.py:529–535`).

### TEsingle

- **Input:** two separate plain GTFs. The TE filename must end exactly `.gtf`; it is shell-sorted before parsing. Gene annotation specifically reads `transcript` rows keyed by `gene_id`, not an exon-only gene file (`T/TEsingle:110–135`). TE rows are parsed without a column-3 type filter; supply just one annotation row per intended block, not redundant gene/transcript/exon representations (`T/TEtools/TEindex.py:287–335`).
- **Attributes and surviving identity:** TE rows require nonempty `transcript_id`, `gene_id`, `family_id`, `class_id`. Its misleadingly named `subf_name` is actually `transcript_id:gene_id:family_id:class_id`; strand is appended only to the internal full name. The four-part label is the matrix feature in `.annots`; `.mtx` is rounded to integers. Sharing only `transcript_id` does **not** combine blocks whose other taxonomy attributes differ (`T/TEtools/TEindex.py:309–335,358–364`; `T/TEsingle:146–169`). No reconstruction from `.out` IDs occurs.
- **Names:** the parser removes `"`, normalizes exactly `; ` to `;`, splits on `;`, then splits each item at its first literal space. Emit `key "value"; key "value";` with one space; tabs or extra spaces between attributes can hide keys. Colon is not rejected inside values, but becomes ambiguous in the composite output; keep each of the four values colon-free. `|` remains literal (`T/TEtools/TEindex.py:299–330`). No automatic TE class/family filter appears in the TE index construction (`T/TEtools/TEindex.py:287–364`).
- **Coordinates/strand/contigs:** TE start/end remain 1-based inclusive; length is `end-start+1`. BAM blocks become `(start+1,end)`. Chromosomes match literal dictionary keys; absent names return no annotation. `--stranded no|forward|reverse`, default forward, compares the selected read direction with GTF strand; there is no paired-end FR/RF orientation option (`T/TEtools/TEindex.py:228–269,293–306`; `T/TEtools/AlignmentIO.py:4–10,65–75`; `T/TEsingle:83–87`).
- **Cell loss:** default `--cutoff 1000` removes a barcode with **fewer than 1,000 distinct UR strings**, before UMI correction/counting. This is not 1,000 TE-assigned UMIs: UR keys are created before testing gene/TE overlap. Exactly 1,000 passes. Tags are hardcoded `CB` and raw `UR`; missing tags or `-`, unmapped/duplicate/QC-failed records are skipped. There is no whitelist option among the CLI arguments. All cells failing gives an exit, while individual cell loss is represented only by the surviving barcode list and aggregate message (`T/TEsingle:75–94,138–167`; `T/TEtools/AlignmentIO.py:26–76`; `T/TEtools/Counters.py:244–250`).
- **Recommendation — premise:** the output preserves a transcript-plus-taxonomy tuple and the cutoff changes the cohort. **Implication:** use record IDs as `transcript_id`, retain raw taxonomy in the other attributes, explicitly set `--cutoff`, and compare surviving CBs with the analysis roster. **Caveat:** mixed-subfamily RepeatMasker instances cannot be represented as one output with truthful per-block taxonomy; treating those as one TEsingle feature needs a separate, explicitly synthetic grouping convention.

### MATES

- **Counting input:** headerless **eight-column CSV plus a same-stem eight-column tab-separated BED companion**: `chrom,start,end,TE_Name,index,strand,TE_fam,length`. CSV alone is insufficient for coverage. `index` must be unique and integer-compatible; `TE_Name` is the subfamily/group label, not the locus identifier. Both files must agree row-for-row (`M/MATES/scripts/count_coverage_10X.py:231–234`; `M/MATES/scripts/make_prediction.py:92–95`; `M/MATES/bam_processor.py:7–23`).
- **Builder inputs are different:** `build_reference.py --species Other` accepts a headered UCSC-style CSV with `genoName,genoStart,genoEnd,strand,repName,repClass` (an index is generated), or its specific `chromStart/chromEnd/name` schema with chromosome header `#"chrom"`; the latter requires `name` to split at `#`. It also requires gene `.gtf` or `.gff3`. This is not a generic TE GTF reader (`M/build_reference.py:44–79`).
- **Names:** direct CSV uses pandas fields; no pipe/colon split defines the group. Generated BED uses `tr ',' '\t'`, so commas are forbidden even inside CSV quoting. Use whitespace-free, quote-free names. Numeric index is used as filenames and joined back to the reference. `TE_fam` controls model grouping/filtering independently of `TE_Name`; auto `.out` uses `class/family`, while the custom UCSC builder uses `repClass` alone—these are different model groupings (`M/build_reference.py:57–62,130–131`; `M/MATES/scripts/Ref2csv.py:73–78`; `M/MATES/scripts/count_coverage_10X.py:117–139`; `M/MATES/scripts/calculate_MU.py:191–194`).
- **Coordinates:** direct coverage expects 0-based half-open intervals, passed unchanged to bedtools/pysam. Auto `.out` extraction does not decrement its 1-based start before writing CSV/BED: an apparent one-base loss. The builder also defaults to clipping long records to 1,000 bases. Its `5prime` mode clips from the low coordinate on **both strands**, and `3prime` from the high coordinate on both, so those option names do not encode biological TE orientation (`M/MATES/scripts/count_coverage_10X.py:16–24,109–133`; `M/MATES/scripts/Ref2csv.py:64–81`; `M/build_reference.py:21–22,142–164`).
- **Strand/contigs:** strand chooses the coverage-vector anchor (start on `+`, end on `-`), but overlap/count calls are unstranded; no library strandedness flag is used in this counting path. The builder heuristically adds chromosome prefixes to genes, consults an hg38 alias file, then removes TE contigs absent from gene annotation. Coverage only rejects total BAM/reference contig disjointness, not partial mismatch (`M/build_reference.py:90–120`; `M/MATES/scripts/count_coverage_10X.py:109–133,255–261`).
- **Auto universe:** Mouse downloads **mm10**, not mm39. Explicit `--ref_mode TE` keeps `DNA,LTR,RC,Retroposon,SINE,LINE`, without a family rule. The actual argparse default is the list `['repeats','TE']`, which does not equal `'TE'` and therefore bypasses that filter. Exclusive reference construction drops whole records overlapping gene bodies (`subtract A=True`); it is not exon subtraction (`M/MATES/scripts/Ref2csv.py:7–23,77–79`; `M/build_reference.py:20,127–135`).
- **Outputs/cells:** subfamily unique counts sum numeric indices into `TE_Name`; predicted subfamily counts merge numeric indices back to that group. Locus MTX `features.csv` carries numeric `TE_index`. Final combined locus H5AD changes feature names to `chrom|start|end|TE_Name`, omitting strand, though numeric `TE_index` remains in var metadata (`M/MATES/scripts/quant_unique_TE.py:85–99`; `M/MATES/scripts/make_prediction.py:151–158`; `M/MATES/scripts/TE_locus_quantifier.py:53–80`; `M/MATES/TE_quantifier.py:15–23,150–153,185–191`). Thus final display names need not be unique.
- **Missing-cell/model support:** barcode lists drive processing; the BAM splitter defaults to `CR`, so select the tag explicitly. No TEsingle-like minimum-cell-UMI gate was found in the audited short-read path. Locus assembly silently skips unreadable per-cell CSVs and only pivots observed cells; combined H5AD can subset unique cells to the multimapping cell list. Model-family support must exceed the default `cut_off=50`; keys ending `?` or exactly `Unknown` are removed from model preparation. These are feature/model-support gates, not cell QC (`M/MATES/bam_processor.py:7,37`; `M/MATES/scripts/TE_locus_quantifier.py:53–67`; `M/MATES/TE_quantifier.py:175–181`; `M/MATES/data_processor.py:7,46`; `M/MATES/scripts/calculate_MU.py:271–295`; `M/MATES/scripts/generatePrediction.py:65–70`).
- **Recommendation — premise:** the direct reference API already accepts externally defined intervals, and the stock builder changes intervals, contigs and grouping. **Implication:** export the final CSV/BED pair directly, with stable registered numeric indices, raw `class/family` in column 7, and no clipping unless explicitly requested. **Caveat:** full-record intervals differ from the stock truncated model input; parsing success cannot establish model validity, and the model-support filters still apply.

### featureCounts SAF and lab convention

- SAF is tab-separated `GeneID Chr Start End Strand`, with a header and 1-based inclusive coordinates. The lab groups by **`Subfamily:Family:Class`**, not bare repName. Multiple rows with one GeneID comprise one meta-feature; record/instance identity does not survive into this grouped count. The recipe extracts quoted attributes with `[^"]+` and constructs the three-part label (`L/te-reference-saf-build/SKILL.md:133–156`; `L/te-reference-saf-build/scripts/build_te_saf.sh:78–86`).
- Exon subtraction converts start to BED with `-1`, subtracts gene exons, and restores start with `+1`, preserving GeneID across remaining blocks. The script strips leading `chr` from both inputs by default. It is not a scaffold-aware alias map (`L/te-reference-saf-build/scripts/build_te_saf.sh:95–124`).
- Driver uses `-F SAF`, TE `-s 0`, with optional sense/antisense passes; featureCounts strand codes are `0/1/2` for unstranded/forward/reverse. Clean output retains the first featureCounts field. **Additional name hazard:** that cleaner uses `printf $1`, so `%` in a name is interpreted as a format directive; forbid it in exports (`L/te-gene-featurecounts/scripts/runFeatureCounts_TE_and_genes.sh:23–41,122–136,144–145`). No cell-barcode processing or annotation auto-download occurs in this driver.
- **Evidence limit:** featureCounts C parser source was not located. Its complete permitted-character set and automatic BAM-contig alias behavior are not certified here. The local lab contract verifies the safe subset, not all possible SAF names. **Recommendation — premise:** the lab consumes triple-keyed no-exon SAF. **Implication:** retain that label order and register triples explicitly. **Caveat:** this is taxonomy-stratified quantification; summing its outputs to bare repName is a later aggregation, and should not be confused with a quantifier fitted directly at bare-subfamily resolution.

### bedtools BED6

- BED6 is `chrom start0 end name score strand`; names are opaque, column 5 is score, and column 6 is strand. Coordinates are passed as integers without shifting; overlap uses `min(end)-max(start)`, i.e. half-open intervals. There is no instance/subfamily inference, taxonomy filtering, or cell threshold (`B/bedFile.h:416–452`; `B/bedFile.cpp:187–198`).
- Literal chromosome keys control overlap. `intersect -s/-S` selects same/opposite strand; absent those flags, strand is ignored in the IRescue bedtools call (`B/bedFile.cpp:187–198`; `I/map.py:316–327`). Output identity depends on the operation: use TE BED as `-a` with `-c`, or retain the TE side of a `-wa -wb` overlap; subtraction preserves its name in each surviving piece, as demonstrated by the lab's conversion back to SAF (`M/MATES/scripts/count_coverage_10X.py:109–110`; `L/te-reference-saf-build/scripts/build_te_saf.sh:115–124`).
- **Recommendation — premise:** six columns give an unambiguous interval/name contract. **Implication:** publish strict BED6 with a record ID for intersections, and keep taxonomy in the catalog. **Caveat:** the available parser source is pybedtools' bundled C++ reader, not a verified source match to the installed bedtools executable. Do not certify arbitrary BED6+ layouts from it; te-tracks' planned 12-field layout needs a real executable test because columns 7–12 have standard BED meanings (`01_modules/te-tracks/docs/OUTPUTS.md:73–80`).

## 2. Minimal exports and common names

### Files, without a Cartesian product

**Premise:** each tool accepts a supplied universe; none requires preserving its auto-downloaded universe. **Implication:** choose one named universe `U` and one exact BAM/FASTA contig namespace, then emit only these cells. **Caveat:** the owner must rule on `U`; format compatibility cannot choose biology. My default proposal is the audited interspersed view (carried classes minus Satellite, without family-prefix exclusion), with all source records retained in the catalog. The legacy and auto-tool universes are optional reproducibility views, not mandatory copies of every export.

| Universe/intervals | Feature level and file | Consumers |
|---|---|---|
| U, original record intervals | `subfamily.bed` (BED6; field 4 bare subfamily) | Direct IRescue subfamily run |
| U, original record intervals | `record.bed` (BED6; field 4 record ID) | IRescue record run; bedtools |
| U, original record intervals | `record.gtf` (exon rows; record and instance attributes) | TEsingle; Stellarscope at either level |
| U minus gene exons | `triple_noExon.saf` | Established lab featureCounts run |
| U, original record intervals | `record.csv` + `record.bed` in a distinct eight-column-format directory | MATES: group in field 4, unique numeric index in field 5 |
| U, original blocks, shared instance names | **Conditional** `instance.bed` (BED6) | IRescue instance run |

That is **six files**, or **seven including instance IRescue**. The MATES pair is mandatory dual serialization, not two biological views. If full-interval SAF is wanted for standalone bulk counting, add it explicitly; the no-exon SAF does not substitute for it. An implementation retaining the lab builder's intermediate `*_all.saf` adds one file beyond the consumer minimum. No separate subfamily/instance GTF, locus SAF, context SAF, or locInd is required for the named workflows. The single GTF carries `transcript_id=record ID`, `gene_id=raw repName`, `family_id`, `class_id`, `locus=record ID`, and `instance_id`; Stellarscope selects `--attribute instance_id` for instance grouping. These choices follow the input keys above (`T/TEtools/TEindex.py:315–330`; `S/cmdopts/stellarscope_assign.yaml:40–51`; `M/MATES/scripts/count_coverage_10X.py:231–234`).

### One lexical grammar, explicit semantic levels

Use a conservative name grammar:

```
atom    := [A-Za-z0-9_.+/?()-]+
name    := atom ( ('|' | ':') atom )*
record  := R|mm39|repName|contig|start1|end1|strand
instance:= I|mm39|repeatmaskerID
triple  := repName:repFamily:repClass
```

Taxonomy components and record/instance IDs used inside TEsingle's four attributes contain **no colon**. Its generated output then has exactly three colon separators. The existing canonical self-description can remain the catalog key; the colon-free exported record alias maps to it. No consumer is required to recover biology by splitting the record alias.

**Premise:** measured absence of `| : , # ~` and whitespace in mm39 taxonomy makes delimiters available, but does not prove absence of every parser hazard. **Implication:** reject whitespace, comma, hash, tilde, quotes, semicolon, backslash and percent in exported names; validate every component against the grammar. For any component outside the safe alphabet, allocate a deterministic safe alias and record the exact raw value. Keep raw taxonomy alongside it. **Caveat:** names needing aliases require decoding before the legacy biological label parser; the registry is authoritative. This grammar is a safe subset inferred from the cited parsers, not an executed cross-tool guarantee (`I/map.py:384–387`; `T/TEtools/TEindex.py:299–330`; `S/annotation/utils.py:60–61`; `M/build_reference.py:130–131`; `L/te-gene-featurecounts/scripts/runFeatureCounts_TE_and_genes.sh:133–136`).

There cannot be one byte-identical output name across all tools: TEsingle constructs four-part labels, MATES has numeric intermediate identities and rewritten H5AD names, and grouped SAF requires the lab triple. The common grammar governs safe serialization; registration governs equality.

### Which tools need instances?

**Premise:** the supplied `.out` ID groups records, including mixed-taxonomy records. **Implication:** only an explicitly instance-level IRescue custom run needs the additional instance-named BED; instance-level Stellarscope can select the shared attribute in the same GTF. Ordinary record runs in both tools, TEsingle, and MATES need per-record intervals/IDs. featureCounts needs shared group IDs; bedtools needs records. **Caveat:** none requires a single bounding-span interval per instance. Preserve disjoint blocks. TEsingle's four-part key can split mixed-taxonomy instances even with a shared transcript ID; MATES's one interval per numeric index is unsuitable for pretending separated blocks are one contiguous locus (parser evidence above).

## 3. Required `te_feature_registration`

**Premise:** quantifier features can correspond to many canonical records. **Implication:** store counts once at the emitted feature grain and use membership as a separate relation. **Caveat:** membership describes support, not evidence that each member produced the count.

Record these fields, using linked tables where repeated metadata belongs at export/run level:

- **Export identity:** catalog BUILD_ID, assembly and source `.out` digest, universe/policy ID, export digest, schema/coordinate version, contig namespace and alias-map digest; gene-GTF digest plus subtraction/clipping rule when applicable.
- **Feature identity:** `(export_id, tool contract/version, output kind, exact emitted ID, output row index)`, display label separately, resolution (`record`, `RepeatMasker_instance`, `subfamily`, `taxonomy_triple`, or explicitly synthetic group), chosen source attribute/column and complete component values. Store both original and exported aliases.
- **Membership:** one unique `(feature_id, canonical_record_id)` edge, plus instance ID and the actual retained interval blocks for that member. Group multiple subtraction pieces under the same edge; include excluded/fully-subtracted status rather than treating an absent row as measured zero. Retain full-source versus selected-universe instance membership so a partially selected instance is identifiable.
- **Tool-specific keys:** IRescue primary ID and display label separately; Stellarscope selected attribute and sentinel status; TEsingle's exact four-part label and its four components; MATES reference numeric index, `TE_Name`, model-group column 7, and final H5AD name **plus row index** (names can collide); SAF GeneID's three components; bedtools original record ID plus output/intersection block identity. These correspond to the output writers cited in §1.
- **Run identity:** analysis_run_id, annotation selection, strandedness and assay/mate layout, counting mode/unit, output matrix digest, cell roster and actual surviving barcodes with exclusion status. Distinguish direct subfamily inference, sums of inferred record counts, unique counts and model-allocated counts. Keep these in run metadata referenced by registration rather than making identical catalog membership run-dependent.

The count fact key is `(analysis_run_id, sample/cell, registered_feature_id, measurement_kind)`. A query selecting records must first select **distinct matching features**, then aggregate their facts once. A feature spanning several records or subfamilies remains one unresolved measurement. Allocation is permitted only as a separate derived measurement with explicit weights summing to one; never attach weight 1 to every member. A mixed-subfamily instance has no automatic subfamily rollup.

**Required conservation test:** feature F has count 7 and belongs to three records; a record membership query still returns total 7, not 21. A second feature with bare repName matching two taxonomy triples still contributes once. A no-exon feature with two remaining blocks contributes once. Separate quantifier runs remain separate facts even when their feature membership is identical.

These are proposed tests, not claimed passes. One successful row proves syntax only; the small adversarial additions prove identity and boundaries. Use a synthetic contig long enough for MATES's ±1,000-base windows, valid nonhomopolymer CB/UMI tags, and records away from contig ends. Repeat the RNA assignment fixtures with separate 3′ ARC and 5′ PE OCM layouts.
