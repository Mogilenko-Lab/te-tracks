## Q1. Stellarscope

**Feature construction.** Default `--feature_type exon` selects GTF column 3; default `--attribute locus` selects the attribute whose value identifies the feature. Rows missing that attribute are skipped with a warning. All retained rows sharing its value enter one `loci[value]`, independently of `gene_id`/`transcript_id`. The reserved `__no_feature` ID must remain distinct (`X/stellarscope/stellarscope/cmdopts/stellarscope_assign.yaml:40–56`; `X/stellarscope/stellarscope/annotation/_intervaltree.py:34–60`).

Overlapping rows within that feature are merged per chromosome, or per chromosome/strand with the stranded annotation class. Larger discontiguous blocks remain separate supports of one feature. A subtle exception: `merge_neighbors(distance=1)` also joins a **one-base genomic gap** because stored intervals are `[GTF_start,GTF_end+1)`; `101..110` plus `112..121` merge, while `113..122` remains separate. Grouping can span chromosomes or strands under one identity, so a shared value itself establishes neither a coherent transcript nor a biological insertion (`X/stellarscope/stellarscope/annotation/_intervaltree.py:49–60,156–166`; `X/stellarscope/stellarscope/annotation/utils.py:17–46`; M4).

**Two overlapping features.** The supported implementation is `--overlap_mode threshold`, default threshold `0.2`. It totals overlap across blocks for each feature, selects `Counter.most_common()[0]`, and accepts that single feature only when overlap is **strictly greater than** aligned-block length × threshold. Exactly 20% fails. Equal overlaps select the first encountered tie, with interval iteration affecting order. It does not send both co-overlapping features from one alignment to EM. Multiple genomic alignments can still supply different selected features. The advertised `intersection-strict` and `union` functions are `pass` stubs returning `None` in this checkout (`X/stellarscope/stellarscope/utils/model.py:519–553,1064,1116–1133`; `X/stellarscope/stellarscope/utils/calignment.pyx:96–104`; `X/stellarscope/stellarscope/cmdopts/stellarscope_assign.yaml:185–200`; M4).

EM pooling defaults to `pseudobulk`, with `individual` and `celltype` alternatives. Default final `best_exclude` selects the highest posterior and excludes posterior ties; this is a later decision than the overlap tie above (`X/stellarscope/stellarscope/cmdopts/stellarscope_assign.yaml:103–147`).

**Boundary defect and consequence.** GTF coordinates remain 1-based in `GTFFeature`; the tree inserts `(start,end+1)`; intersection queries take pysam's 0-based half-open blocks and also add one to their end. Those incompatible conventions cause the error (`X/stellarscope/stellarscope/annotation/utils.py:77–96`; `X/stellarscope/stellarscope/annotation/_intervaltree.py:55,78–84`; `X/stellarscope/stellarscope/utils/calignment.pyx:96–101`). Against GTF `101..110`, one-base queries `[99,100)`, `[100,101)`, `[109,110)`, `[110,111)` produce overlap lengths **0,1,2,1**, hence presence **0,1,1,1** instead of **0,1,1,0** (M4; `tests/checks/consumers/11_stellarscope_parser.py:48–57`; `docs/OUTPUTS.md:504–506`).

The right-adjacent base gains false support; interior/block overlap can gain a base and move a read across the threshold or change the winning record. Effects then propagate into candidate sets and EM counts. A one-base false overlap alone usually fails the default threshold for a long read, so the fixture does not imply that every adjacent real read is counted. The practical gate is endpoint/threshold/overlap-tie qualification of a pinned corrected consumer; retain canonical GTF coordinates (`X/stellarscope/stellarscope/utils/model.py:529–537`; inference from the measured overlaps).

**Exports.** `record.gtf --attribute locus` counts record aliases; the same file with `--attribute instance_id` groups source-instance fragments; `subfamily.gtf` with default `locus` groups by `rmsk_name`. The registration pairs are respectively `(record,record_alias)`, `(instance,instance_alias)`, `(subfamily,rmsk_name)`, scoped to universe/variant. The existing fixture checks 11 records, 10 instances and the large instance gap before reporting the boundary defect as unsupported (`docs/OUTPUTS.md:347–383,420–429`; `tests/checks/consumers/11_stellarscope_parser.py:20–57`).

**Documented STAR recipe.** The Stellarscope protocol recommends `--outFilterMultimapNmax 500 --outFilterMultimapScoreRange 5`, coordinate-sorted BAM, `--outSAMunmapped Within`, and `--outSAMattributes NH HI AS NM nM MD CR CY UR UY CB UB GX GN sS sQ sM`. Its human 3′ example uses `CB_UMI_Simple`, barcode positions/lengths `1/16`, UMI `17/12`, the chemistry whitelist, `--clipAdapterType CellRanger4 --outFilterScoreMin 30 --soloCBmatchWLtype 1MM_multi_Nbase_pseudocounts --soloUMIfiltering MultiGeneUMI_CR --soloUMIdedup 1MM_CR`, and `--limitOutSJcollapsed 5000000`. It specifies neither `winAnchorMultimapNmax` nor `outSAMmultNmax`; those require an explicit consumer choice (`X/stellarscope/docs/protocol.md:244–258,265–295`).

## Q2. IRescue

**Native names and locus modes.** Automatic RepeatMasker conversion writes `subfamily#class/family` at subfamily level; class-only source labels omit `/family`. Fragment mode appends `~index`, a counter within that compound name. Instance mode repeats `subfamilies#classes/families~instance` across the source instance's original intervals; distinct subfamilies/classes/families are sorted and pipe-joined separately. Thus mixed-name instances receive one compound feature without replacing their intervals by a bounding span (`X/irescue/irescue/map.py:125–159,160–193`).

The actual CLI option is `--locus-level {disabled,fragment,instance}`, default `disabled`; it requires a value. README examples showing bare `--locus-level` omit that value. A supplied `-r BED` bypasses conversion, regardless of the locus argument: its column 4 already defines the counted grouping. Locus mode still affects the display-name formatting described below (`X/irescue/irescue/main.py:102–113`; `X/irescue/irescue/map.py:38–50,61–84,382–388`; `X/irescue/README.md:108–115`).

**Custom BED parsing and taxonomy.** `count.py` never splits column 4 into subfamily/class/family: `index_features` indexes the exact first column of `features.tsv.gz`, while `parse_maps` splits comma-separated feature lists into a set of those IDs. Mapping obtains the BED name via the intersection's column 16 and deduplicates repeated feature hits (`X/irescue/irescue/map.py:325–332,366–377`; `X/irescue/irescue/count.py:57–93`).

`map.py` writes three feature columns: **unchanged ID**, display name, literal `Gene Expression`. Its `gensub` strips `#...` from the display name; locus mode preserves the `~suffix`, disabled mode strips it along with taxonomy. For te-tracks `record.bed` names `name|chrom:start-end|strand`, and `subfamily.bed` names `rmsk_name`, there is no `#`: ID and display name are identical, and class/family occur nowhere in that output. Obtain them by registration/taxonomy joins. Even native compound names carry taxonomy as text in column 1, rather than separate taxonomy columns or class/family matrices (`X/irescue/irescue/map.py:382–388`; `X/irescue/irescue/count.py:57–63,424–439`; `docs/OUTPUTS.md:322–336`; M5).

**A possible taxonomy-bearing profile.** A parser-compatible `record_irescue.bed` could use `<rmsk_name>#<class_id>/<family_id>~<record_alias>`, with canonical or positional unresolved rank tokens. The suffix is opaque to the counting parser; the converter itself uses numeric indices. Register the exact whole name under proposed `(record,irescue_record_v1)`, one full block/member, scoped by `interspersed/full`; use `--locus-level fragment` to retain the suffix in the display label. A subfamily variant could use `<rmsk_name>#<class_id>/<family_id>` and `(subfamily,irescue_subfamily_v1)`. Both preserve encoded taxonomy in column 1; extracting rank columns remains a consumer operation (`X/irescue/irescue/map.py:135–141,382–388`; `X/irescue/irescue/count.py:57–84`).

These would require dedicated `#`/`~` serialization validation, reserved delimiters and new registration grammars: the current exporter rejects both characters. Preserve the comma prohibition because commas delimit alternative features. Canonical labels keep a name's grouping stable across its raw taxonomy disagreements (`src/lib/build_exports.py:22–23,152–179`; `tests/checks/consumers/10_irescue_parser.required.py:42–54`; `docs/OUTPUTS.md:210–218,408`). Recommend the existing BEDs plus joins for the pilot; an extra BED profile supplies portable taxonomy text while retaining the same count model.

**Overlap and EM.** Mapping uses `bedtools intersect -split -wo`; every intersecting named feature can enter the equivalence class. Optional base/fraction thresholds apply at intersection; default strandedness is `unstranded`, and both thresholds default to disabled. Repeated names across fragments become one feature competitor; a read confined to a genuine gap has no TE interval hit (`X/irescue/irescue/map.py:310–332,369–375`; `X/irescue/irescue/main.py:136–165`; `X/irescue/irescue/count.py:79–84,203–208`).

A separate qualification issue emerged: this checkout fixes single-feature UMI counts separately, runs EM on ambiguous molecules with uniform initialization, then adds the fixed counts. Unique support does not seed that EM. Our isolated calls with four A-only, two B-only and three A/B molecules returned **5.5/3.5**, including with distinct UMIs; symmetric 3/3 support returned **4.5/4.5**. The executable fixture expects **6/3** for the first case. Preserve this as an unresolved consumer/oracle discrepancy; no fixture was changed (`X/irescue/irescue/count.py:203–208,249–297`; `X/irescue/irescue/em.py:60–79`; `tests/lib/consumers.py:563–578`; M5).

**Contigs and alignment.** Reference names match exactly. `getRefs` selects BAM references with mapped reads, warns and skips names absent from the BED, and errors if none remain; its ENSEMBL/UCSC message performs no renaming. Select te-tracks' namespace by the actual BAM dictionary; for the supplied 10x GEX reference it is `gencode` (M1; `X/irescue/irescue/map.py:212–249`).

The README recommends retained secondary alignments with at least `--outFilterMultimapNmax 100 --winAnchorMultimapNmax 100`, and `--outSAMattributes NH HI AS nM NM MD jM jI XS MC ch cN CR CY UR UY GX GN CB UB sM sS sQ`. Input is coordinate-sorted, indexed BAM; default tags are `CB`/`UR`, and a viable-cell roster is recommended with `-w` (`X/irescue/README.md:96–104,130–134`; `X/irescue/irescue/main.py:85–100`).

## Q3. STARsolo GeneFull, combined GTFs and cellranger

**External STAR contract, unverified here:** under the normal GTF defaults, exon rows supply contig, 1-based inclusive bounds, strand, `gene_id` and `transcript_id`; transcript/gene rows alone do not substitute for exon support. `gene_name` supplies the human-readable feature label, with ID fallback when absent. `gene_type`/`gene_biotype` are metadata, not the grouping identity or a requirement to label a TE as protein coding. The local benchmark verifies use of a combined GTF and `GeneFull`, but does not vendor STAR's parser (`X/TEsingle_benchmarking_scripts/index_generation/T2T_STAR_index_generation.sh:46–62`; `X/TEsingle_benchmarking_scripts/software_running/T2T_STARsoloTE.sh:48–52`).

**External STAR output semantics, unverified here:** `features.tsv` follows gene order, with columns gene ID, gene name, `Gene Expression`; Matrix Market row indices refer to that order. `--soloMultiMappers EM` produces `UniqueAndMult-EM.mtx`, containing unique counts plus fractionally allocated ambiguous counts; the ordinary `matrix.mtx` is the unique-only output, so adding the two duplicates unique support. The benchmark directly consumes `Solo.out/GeneFull/raw/{features.tsv,barcodes.tsv,UniqueAndMult-EM.mtx}` (`X/TEsingle_benchmarking_scripts/accuracy_calculations/calculate_STARsoloTE_accuracy.sh:30–45`). Qualify the exact STAR version's GeneFull multi-annotation and UMI behavior on the gene–TE fixture, including a unique genomic alignment compatible with both annotations.

Join TE matrix rows using **features column 1**, through `(universe_name=interspersed, variant=full, feature_level=record, key_grammar=record_alias, emitted_feature_id=gene_id)`, then to the catalog. Preserve raw fractional counts and filter cells by the same retained roster. `gene_name=rmsk_name` is deliberately repeated and serves display/rollup metadata. The scoped binding corrects the abbreviated pair-only sentence in `docs/OUTPUTS.md:436–440`, as C9 requires; aliases and registration are namespace-invariant (`docs/OUTPUTS.md:414–432`; `C/adr_rulings_2026-09-17.md:52`; M2).

**What the paper checkouts establish about GTF grammar.** The index scripts require pre-existing `T2T_geneTE_forSTAR.gtf` and `T2T_geneTE_forCellRangerTE.gtf`; their rows and generation recipe are absent. README points to an external ZIP. Consequently these scripts cannot establish the exact paper attributes, their order, or the CellRanger TE gene-ID grouping (`X/TEsingle_benchmarking_scripts/README.md:59–89`; `X/TEsingle_benchmarking_scripts/index_generation/T2T_STAR_index_generation.sh:46–62`; `X/TEsingle_benchmarking_scripts/index_generation/T2T_CellRangerTE_mkref.sh:39–49`).

The locally supplied dissertation excerpts explicitly define subfamily GTF as `gene_id=subfamily`, `transcript_id=locus`, with family/class fields, and loci GTF as `gene_id=transcript_id=locus`; the latter joins the gene GTF during STAR index generation (`C/thesis_2023_excerpts.md:102–109,134–145`). This establishes the intended locus model, while the paper's actual combined files remain uninspected. Its STAR accuracy script treats differing ID/name fields as TE and aggregates `_dup` loci; its CellRanger accuracy script groups **column 2** to subfamilies. Those are downstream assumptions, not proof of the missing GTF bytes (`X/TEsingle_benchmarking_scripts/accuracy_calculations/calculate_STARsoloTE_accuracy.sh:36–54`; `X/TEsingle_benchmarking_scripts/accuracy_calculations/calculate_cellrangerTE_accuracy.sh:29–42`).

**mkgtf/mkref.** The benchmark runs `mkref --genome ... --fasta ... --genes ... --nthreads 10`; it contains no `mkgtf` call. The printed script also leaves `GENOME` undefined and its outer executable-presence `if` unclosed, so it is provenance rather than a ready-to-run recipe (`X/TEsingle_benchmarking_scripts/index_generation/T2T_CellRangerTE_mkref.sh:15,39–56`). The dissertation describes filtering the **gene** annotation by selected biotypes before combining it with TE loci (`C/thesis_2023_excerpts.md:125–145`).

**External 10x contract, unverified here:** CellRanger treats each `gene_id` as the counted feature; it has no separate TE-locus identity. `mkref` needs a matching FASTA and valid exon-bearing GTF with consistent gene/transcript IDs; gene names are display metadata. `mkgtf` is an attribute-filtering preprocessing step, with acceptance controlled by the requested filter. Custom TE biotype text can be retained by explicitly including it, or by filtering genes first and appending TE rows afterwards. Recommend `gene_type "transposable_element"`; use the actual attribute key when filtering—the supplied mouse GTF has `gene_type`, while every exon lacks `gene_biotype` (M1). Executable qualification must establish that the chosen CellRanger version accepts the alias characters and this custom label. Reference acceptance alone establishes neither STARsolo EM equivalence nor locus-count accuracy.

**Collision rules.** Before combining, require unique TE `gene_id`/`transcript_id` per record, a single consistent gene for each transcript, and empty intersections with host gene IDs and host transcript IDs respectively; also reject host use of the reserved `R|mm39|` identity prefix. Repeated host IDs across their own exons are expected. Overlapping coordinates and repeated gene names remain valid distinct features. Abort on a collision; a consumer rename needs its own mapping, digest and registration binding. Measured collisions against the provided GTF: **zero genes, zero transcripts** (M1). These are proposed preflight rules grounded in the alias contract (`docs/OUTPUTS.md:351–354,422–424`).

**Namespace and pins.** The 10x dictionary has 61 contigs: 22 conventional `chr` names plus 39 accession names. `chrom_gencode` matches all 61 names and lengths; `chrom_ucsc` matches 22 names, `chrom_ensembl` 39. Interspersed exports use 59 contigs; `chrM` and `JH584295.1` have zero interspersed support. Match by name/length dictionary, not row order (`B/tables/contig_aliases.tsv:1–62`; `R/star/chrNameLength.txt:1–61`; `docs/OUTPUTS.md:526–545`; M1). This GEX M33 reference is a verified example; the 14761 ARC FASTA/GTF pin still needs its own comparison (`R/genes/genes.gtf.gz:1–8`; `C/adr_rulings_2026-09-17.md:82–89`).

## Q4. Instances as one competitor and gap reads

| Tool | Can fragments form one competitor? | Gap/read and EM consequence |
|---|---|---|
| Stellarscope | Shared `instance_id` groups rows and merges overlapping support per contig/strand. | Large gaps stay unsupported; one-base gaps and endpoints have Q1's defects. Per-alignment maximum-overlap selection precedes EM (`X/stellarscope/stellarscope/annotation/_intervaltree.py:49–60,78–84`; `X/stellarscope/stellarscope/annotation/utils.py:17–46`; `X/stellarscope/stellarscope/utils/model.py:519–551`). |
| IRescue | Instance conversion repeats one compound BED name; an equivalent custom BED can do so directly. | Candidate sets deduplicate that name, so fragments cease competing with one another. Original intervals preserve gaps; overlap thresholds operate on intersected rows (`X/irescue/irescue/map.py:160–189,312–332,369–375`; `X/irescue/irescue/count.py:79–84,255–257`). |
| STARsolo | **External STAR knowledge, unverified here:** one gene, one transcript, one exon row per fragment defines one feature. | `Gene` uses exon support; `GeneFull` includes the gene span and therefore its gaps. A gap-only read can become instance evidence under GeneFull. The single-exon locus precedent is local (`C/thesis_2023_excerpts.md:102–109,151–155`); multi-exon behavior needs the proposed executable fixture. |
| TEsingle | Each row is indexed, then row hits are translated to a **deduplicated four-tuple feature index before counting**. Identical `transcript_id:gene_id:family_id:class_id` therefore can form one competitor. | Both fragments return the same count index; gaps remain unsupported. Repeating only `transcript_id` while other tuple fields differ preserves multiple competitors. This corrects the earlier joint TEsingle/TElocal claim (`X/TEsingle/TEtools/TEindex.py:252–275,329–364`; `X/TEsingle/TEsingle:146–149`; M6). |
| TElocal | Each row remains a separate indexed entry and EM competitor, even with identical four-tuples; output aggregation joins equal element names later. | Gaps remain unsupported; fragments retain separate competition until reporting (`X/TElocal/TElocal_Toolkit/TEindex.py:325–365,419–455`; `X/TElocal/TElocal:295–296,459–465,157`; M6). |

TEsingle's `subfLengthDict` sums row lengths rather than computing a block union; its inspected EM initializes from count vectors and makes a final hard argmax assignment. A grouped annotation therefore needs an explicit overlap/metadata policy even when it produces one competitor (`X/TEsingle/TEtools/TEindex.py:333–335`; `X/TEsingle/TEtools/EM.py:30–35,55–61,114`). The thesis prototype's annotation separately intersects gene and TE intervals using strand-aware split overlaps; that is evidence about its prototype, not about STAR's parser (`X/Thesis_2023/quantification_method/eqc_generation/scripts/annotate.sh:21–35`).

Recommend deferring `instance_starsolo.gtf`: the interspersed instance set includes **30,569 mixed-name** and previously measured **23,244 mixed-strand** instances, making a single transcript's taxonomy/strand a separate design decision. GeneFull additionally fills instance gaps and a multi-exon transcript can introduce assumed splice junctions into the index (the latter is **external STAR knowledge, unverified here**). Require block-union, mixed-strand, gap-read and junction tests first (`docs/OUTPUTS.md:440–441`; `C/field_practice_consult.md:96`; `X/TEsingle_benchmarking_scripts/index_generation/T2T_STAR_index_generation.sh:62`).
